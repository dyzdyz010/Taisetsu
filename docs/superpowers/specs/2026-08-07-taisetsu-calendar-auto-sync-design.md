# Taisetsu 日历自动同步设计

- 状态：已通过会话评审
- 日期：2026-08-07
- 影响范围：EventKit 日历权限、自动同步引擎、设置页、提醒引导、SwiftData 同步映射与发布签名配置

## 1. 产品定义

功能名称统一为“日历自动同步”，不再使用容易被理解为单次导出的“日历同步状态”或“日历导出”作为主功能名称。

同步是单向的：Taisetsu 是唯一数据源，系统日历是展示和提醒渠道。系统日历中的手动修改会在下一次对账时恢复为 Taisetsu 内的数据；不实现系统日历到 Taisetsu 的双向同步。

## 2. 权限模型

自动同步需要查找、更新和删除由 Taisetsu 创建的事件，因此申请 EventKit 的完整日历访问权限。只写权限不能满足持续对账需求。权限状态映射为：

| 状态 | 界面表现 | 操作 |
| --- | --- | --- |
| `notDetermined` | 红色“未授权” | 开启自动同步并触发系统授权 |
| `fullAccess` 且同步正常 | 绿色“已开启” | 查看范围和同步详情 |
| `writeOnly` | 红色“权限不足” | 引导升级为完整访问 |
| `denied` | 红色“已拒绝” | 前往系统设置 |
| `restricted` | 红色“受系统限制” | 展示原因，不重复请求 |
| 已授权但有失败 | 橙色“同步异常” | 查看失败数量并重试 |
| 同步执行中 | 蓝色进度状态 | 禁止重复启动同步任务 |

系统权限弹窗只在 `notDetermined` 时触发；用户拒绝后不重复请求系统弹窗，只提供系统设置入口。使用 `NSCalendarsFullAccessUsageDescription`，并为所有支持语言提供完整本地化文案。

## 3. 主动提醒

用户创建第一个重要日并关闭编辑页面后，立即展示自定义同步说明：

- “开启自动同步”
- “稍后提醒”
- “再也不提醒”

选择“稍后提醒”后，在应用重新进入前台且达到下一次提醒日期时触发，间隔为：

`1 → 2 → 4 → 8 → 16 → 32 → 64 天 → 每 90 天一次`

后续创建新重要日不会绕过当前冷却时间。选择“再也不提醒”后永久关闭主动弹窗，但设置页入口始终保留。该选项和退避计数保存在设备本地，因为日历权限是设备级权限。

用户从设置页主动开启同步后清除退避计数。权限后来被撤销时，状态立即变红；除非用户选择过“再也不提醒”，否则从下一次创建重要日开始重新进入提醒周期。

## 4. 同步目标

首次开启自动同步时创建独立的系统日历，显示名称固定为 `Taisetsu`：

- 所有自动同步事件只写入该日历；
- 不写入用户当前默认日历；
- 目标日历被用户删除后，应用自动重建并重新同步；
- 目标日历不可写或创建失败时，设置页显示橙色错误状态；
- 目标日历名称是品牌名，不随语言翻译。

## 5. 同步范围

默认同步全部重要日。设置页允许改为自定义范围：

- 分类多选；
- 标签多选；
- “未分类”选项；
- “无标签”选项。

组合规则为：

- 分类内部多选取并集；
- 标签内部多选取并集；
- 分类和标签之间取交集；
- 未限制某个维度时，该维度全部通过。

修改范围后立即自动对账，移出范围的事件自动删除。

## 6. 事件生成

使用滚动窗口同步未来两年，每次 occurrence 创建为独立系统日历事件。这样可以统一支持公历、农历、自定义间隔、闰日和复杂重复规则，不依赖系统日历的公历重复规则。

为控制高频规则的事件数量：

- 每个重要日最多保留距离当前最近的 128 次 occurrence；
- 全部重要日最多同步 1,000 个事件；
- 达到上限时优先保留最近事件，后续对账时滚动补充；
- 设置页展示实际同步数量，必要时提示高频规则受到数量上限影响。

应用启动、回到前台、重要日新增或修改、重要日删除、同步范围修改以及权限变化时触发对账。可以注册后台刷新任务作为最佳努力，但前台恢复时必须重新校正，不能依赖后台任务保证一致性。

## 7. 数据结构与迁移

现有 `calendarEventIdentifier` 只能表示一个事件，新增独立的同步映射模型 `CalendarSyncEntry`，至少包含：

- `anniversaryID`；
- occurrence 唯一键；
- EventKit 事件 ID；
- Taisetsu 目标日历 ID；
- 最后同步时间；
- 同步状态和错误信息。

现有单事件导出数据迁移规则：

1. 旧事件仍存在时，将其迁移到 Taisetsu 日历并复用事件 ID；
2. 旧事件不存在时，忽略旧 ID 并重新创建；
3. 按未来两年窗口补齐其他 occurrence；
4. 不删除无法确认由 Taisetsu 创建的事件。

## 8. 同步行为

新增重要日：保存本地数据、触发首次提醒或同步、计算窗口、写入 Taisetsu 日历并保存映射。

修改重要日：更新仍匹配的事件、删除失效 occurrence、创建新增 occurrence。

删除重要日：删除该重要日关联的全部 Taisetsu 事件，再删除本地记录。

Taisetsu 内的标题、日期、备注和全天状态是最终值。系统日历中手动修改或删除事件，会在下一次对账时被恢复或重建。

停用自动同步时，删除 Taisetsu 创建的全部系统日历事件，但保留重要日数据和同步范围；以后重新开启时重新生成窗口内事件。

## 9. 设置页

设置页新增独立的“日历自动同步”卡片，展示：

- 当前状态颜色；
- 目标日历名称；
- 当前同步事件数；
- 上次成功同步时间；
- 同步范围摘要；
- 最近一次错误和失败数量。

点击卡片进入“同步范围”页面，支持全部/自定义、分类多选、标签多选和预计同步数量。页面还提供“停用自动同步”操作和系统设置入口。

## 10. 错误处理

以下情况必须有可见状态且不能静默失败：权限拒绝、权限撤销、日历不存在、日历不可写、单个事件创建失败、单个事件删除失败、occurrence 计算失败和无效事件 ID。

部分事件失败时，保留成功事件、记录失败事件、展示橙色状态并在下次前台恢复时自动重试。不得重复创建已经成功的事件；无法证明所有权时不得删除事件。

## 11. 测试

单元测试覆盖：两年 occurrence 窗口、128 条单项上限、1,000 条总量上限、分类与标签交集、未分类/无标签筛选、增删改同步计划、指数退避、“再也不提醒”、权限状态映射和迁移逻辑。

集成测试使用 EventKit 客户端替身覆盖：创建目标日历、批量创建/更新/删除、删除后重建、旧单事件迁移、部分失败重试和范围变化清理。

UI 测试覆盖：绿色/红色/橙色状态、创建后立即出现引导、三个提醒操作、系统设置跳转、范围筛选和中英文文案。

真实 EventKit 权限与签名验证在本机开发设备执行；CI 使用替身，不依赖个人 Apple ID 或真实日历数据。

## 12. Apple 开发者账号与安全

实现和发布时使用用户已购买的 Apple Developer 账号登录 Xcode 和开发者网站，配置正确的开发团队、证书、Provisioning Profile、iCloud 和 Push Notifications 能力。

Apple ID 邮箱、密码、证书私钥、Provisioning Profile 和登录凭证不得写入 Git 仓库或 CI 日志。项目只保存 Apple 分配的 Team ID 和必要的 Bundle Identifier；最终签名配置由本机 Keychain 与 GitHub Secrets 管理。

## 13. 明确排除

- 不实现系统日历到 Taisetsu 的双向同步；
- 不读取或导入用户已有的普通日历事件；
- 不把事件写入用户默认日历；
- 不创建系统级通知替代现有提醒功能；
- 不保证应用被系统完全终止后仍持续后台同步；
- 不把 Apple ID 或签名私密材料提交到仓库。
