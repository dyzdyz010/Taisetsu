# Lunar Recurrence Clarity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make lunar recurrence semantics visible before and after saving so a monthly lunar rule cannot be mistaken for an annual same-date anniversary.

**Architecture:** Keep `OccurrenceCalculator` as the only recurrence engine. Add a focused app-layer preview adapter from `AnniversaryDraft` to `AnniversaryRecord`, add localized lunar month/day formatting to `AnniversaryFormatters`, and reuse both in the editor and detail screen. Preserve persistence and all existing recurrence semantics.

**Tech Stack:** Swift 6, SwiftUI, Foundation Chinese calendar, Swift Testing, Xcode String Catalogs, XcodeGen

## Global Constraints

- Do not change the SwiftData schema or automatically migrate existing recurrence rules.
- Preserve day, week, month, and year recurrence for Gregorian and Chinese-lunar records.
- Use the real `OccurrenceCalculator`; do not duplicate recurrence logic in SwiftUI.
- Localize every new user-visible string for `en`, `zh-Hans`, `zh-Hant`, `ja`, `ko`, `es`, `fr`, `de`, `pt-BR`, `it`, and `ar`.
- Work directly on `main`, push without a pull request, and keep the working tree clean.

- [ ] **Step 1: Write the failing app-layer tests and the independent core fixture**

Add a core characterization fixture asserting that lunar 1992 month 8 day 4 repeated yearly resolves next to `2026-09-13T16:00:00Z` from `2026-08-03T04:00:00Z` in Asia/Shanghai. Add app tests with literal expectations:

```swift
@Test func lunarMonthRecurrencePreviewExposesTheShiftedLunarMonth() {
    var draft = AnniversaryDraft()
    draft.calendarKind = .chinese
    draft.date = AnniversaryDate(year: 1992, month: 8, day: 4)
    draft.recurrenceUnit = .month
    draft.recurrenceInterval = 6

    let next = RecurrencePreview.nextOccurrence(
        for: draft,
        relativeTo: date("2026-08-03T04:00:00Z"),
        timeZone: TimeZone(identifier: "Asia/Shanghai")!
    )

    #expect(next == date("2026-08-15T16:00:00Z"))
    #expect(RecurrencePreview.explainsLunarMonthInterval(for: draft))
}
```

Add formatter assertions for English `Lunar month 8, day 4`, Simplified Chinese `农历8月4日`, and a leap-month fixture `农历闰11月29日`. Assert that the combined English output is exactly `Sep 14, 2026 · Lunar month 8, day 4`. Expected strings must be literals, not generated by a Chinese `Calendar` in the test.

- [ ] **Step 3: Implement the minimal preview adapter**

Create `RecurrencePreview` as a namespace enum. Return `nil` when recurrence is disabled or calculation fails. Otherwise construct an `AnniversaryRecord` from the draft's calendar kind, date, all-day flag, recurrence rule, and display mode, then return `OccurrenceCalculator().calculate(...).next`. The explanation predicate returns true only for Chinese-lunar records with recurrence unit `.month`.

- [ ] **Step 4: Implement localized lunar formatting**

Format through `AppLocalization.format` using `Lunar month %lld, day %lld` or `Leap lunar month %lld, day %lld`. `dateWithLunar` joins the Gregorian date and lunar value with ` · `.
